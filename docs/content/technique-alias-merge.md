# Technique alias merge — curriculum vocabulary onto seeded rows

**Status: APPLIED** (2026-08-06). The aliases are in the spreadsheet and in
`techniques.json`; the catalog went from 855 aliases to 1,057. This file stays
as the record of what was merged and why, and the CSV as the artifact that was
applied — re-running the apply script now correctly refuses, because the cells
already hold the merged value.

**What this is:** 202 aliases for 130 existing techniques, extracted from the
BJJ curriculum master document and mapped to the rows they actually name.
Generated by [`scripts/build-alias-merge.py`](../../scripts/build-alias-merge.py),
applied by [`scripts/apply-alias-merge.py`](../../scripts/apply-alias-merge.py);
the artifact between them is
[`technique-alias-merge.csv`](technique-alias-merge.csv).

**Why it is a spreadsheet task and not a code change.** `techniques.json` is a
build artifact. `scripts/import-exercise-catalog.py` regenerates it from the
authoring spreadsheet as a **full replacement**, and `cmd/exportcontent`
refuses to write a sheet-owned id into `techniques.additions.json`. So an alias
added to a seeded row by editing JSON survives exactly until the next
re-import, then disappears with nothing reporting a fault. The sheet is the
only durable route for these 130 rows. (Of the 542 techniques, 92 are carried
in `techniques.additions.json` and this repo owns them — they already have
their aliases. The other 450 are the sheet's, and these 130 are the subset the
curriculum had vocabulary for.)

## Why aliases and not descriptions

The list endpoint returns summaries, and a summary has **no description field**
(`Summary` in `backend/internal/modules/technique/technique.go`). Search
therefore runs over name, aliases, position, detail, category and function —
so a name someone actually says, but that appears in none of those, is
unreachable no matter how well the ranking works.

**Measured against the shipped scorer: 99 of these 202 aliases are strings that
return _zero_ results today and land on the right technique after the merge.**
"honey hole" (0 → 2), "rodeo ride" (0 → 1), "turk" (0 → 1). The other 103 are
already reachable and buy ranking rather than reachability — an exact alias
match is worth +4,000 in `scoreTechnique`, so they pull the right row to the
top of a list it was merely present in.

Note this is no longer about spelling variants: the search work that landed
alongside matches each query term as a **substring**, so "arm bar" already
finds `Armbar from Closed Guard` with no alias at all. What is still missing is
*different words for the same thing*, which is exactly what a curriculum's
`aka` parentheticals are.

## How it was applied

```bash
python3 scripts/apply-alias-merge.py <techniques.xlsx>
python3 scripts/import-exercise-catalog.py - <techniques.xlsx>
# review techniques.generated.json, then promote it over techniques.json
cd backend && go run ./cmd/seed
```

The apply step is **all-or-nothing**: every target row is located and its
current `aliases` cell compared against the CSV's `current_aliases` before
anything is written, and one mismatch aborts with the file untouched. That
check is the whole safety of the operation — the CSV holds a whole cell rather
than a delta, so applying it to a sheet that had since gained an alias would
silently delete that alias, and a missing alias looks exactly like one nobody
wrote.

Re-running after a successful apply **fails** rather than quietly doing
nothing, because "already applied" and "drifted since generation" are the same
observation from the outside and both want a human.

The cell splits on both `;` and `,`, so no alias here contains either
character — verified, not assumed.

Two byte-identical copies of the spreadsheet existed (`~/Downloads` and
`~/Documents/Codex/2026-07-24/ta/outputs/…`); both were updated, and both had a
timestamped `.bak` written first. Before the merge, each regenerated
`techniques.json` **byte-for-byte** — which is what identified them as the real
authoring surface rather than stale exports.

## What was dropped, and why

Of the curriculum's alias strings that reached a mapped row, **88 were not
carried**:

| Reason | Count |
| --- | --- |
| Already exists in the catalog — a duplicate alias resolves ambiguously | 46 |
| Too generic to disambiguate, or names a **different** technique the library already has | 42 |

The second class is the dangerous one, and each is listed explicitly in the
script's `SKIP_ALIAS` set with the row it would have collided with. Six
examples, all of which would have made search answer with the wrong technique:

- **"Far Side Armbar"** was offered for the near-side armbar row —
  `Far-Side Armbar from Side Control` is its own technique.
- **"Waiter Sweep from Guard"** was offered for the lumberjack sweep —
  `Waiter Sweep` is its own row and `Deep-Half Waiter Sweep` a second.
- **"Granby Roll Escape"** was offered for the bridge-and-roll side escape.
  A granby is not a bridge-and-roll, and four granby rows exist.
- **"Tekubi Hishigi"** was offered for the toe hold — in judo that name is a
  **wrist** lock.
- **"Half Smash Pass"** was offered for the generic `Smash Pass` —
  `Knee-Shield Smash Pass` *is* the half-guard smash, and gains the synonymous
  "Smash Pass from Half" in this same merge.
- **"Crab Ride to Twister"** was offered for `Calf Slicer from the Truck` — it
  names the twister, which has its own row.

**189 curriculum lines with aliases produced nothing here.** Most name a row
this repo owns (already aliased at authoring) or a technique that was
deliberately not added. That is the expected outcome, not a shortfall.

## Six mappings reviewed and kept

Each of these aliases also fits some other row's *name*, so the generator
flags them (that check is what caught "Far Side Armbar"). All six are correct
where they are — the alias is the canonical synonym for its row, and the row it
also resembles is a more specific technique:

| Alias | Placed on | Also resembles |
| --- | --- | --- |
| High Guard | Rubber Guard Mission Control | High-Leg Guard Recovery |
| Back Take from Side | Side-Control Back Take | Kimura-Trap Back Take from Side Control |
| Underhook Guard Pass | Underhook Knee-Cut Pass | Near-Side Underhook Half-Guard Pass |
| Chest Mount | High Mount Control | Chest-Compression Choke from Mount |
| Lapel Guard | Worm Guard Control | Overhook Lapel Choke from Closed Guard |
| Headlock Control | Kesa Gatame Control | Front-Headlock Chin-Strap Control |

## Judgment calls worth a second look

Five entries carry the curriculum's own vocabulary where the library would
arguably file it differently. They are kept because they are how the user's
gym says it, but they are the ones to strike if search gets noisy:

- **"Hip Heist Sweep from Guard"** on `Knee-Push Sweep` — "Hip Heist Sweep"
  separately maps to `Old-School Sweep`, and `Turtle Sit-Out to Guard` already
  carries "Hip heist", so a "hip heist" search goes from 3 rows to 5.
- **"Sickle Sweep from Closed Guard"** on `Pendulum Sweep` — the library has
  two dedicated sickle sweeps (De La Riva, collar-sleeve).
- **"Leg Drag from Half"** on `Knee-Shield Leg-Weave Pass` — a weave is not a
  drag, and `Leg-Drag Pass` gains the bare "Leg Drag" in the same merge.
- **"Stand-Up in Base"** as an alias of `Technical Stand-Up`, while the
  mapping table reads the identical curriculum line as `Stand-Up from Turtle`.
  Both are defensible; they should not both be true.
- Family names landing on one member: **"Double Wristlock"** and **"Gyaku Ude
  Garami"** on `Kimura from Closed Guard`, **"Shoulder Lock"** on
  `Omoplata from Closed Guard`. An alias lives on exactly one row, so the
  most-taught member gets it.

## Regenerating the list

```bash
python3 scripts/build-alias-merge.py <curriculum.md>
```

The mapping table lives in the script (`HAND`), hand-curated rather than
scanner-derived: `scripts/scan-library.py` matches a technique as
MOVE × POSITION, which is right for finding gaps and wrong for deciding which
single row a synonym belongs to.
